# 与项目文档衔接

写入前完整使用 `$write-project-docs`。本 Skill 只提供从 MasterGo 读取的原型事实，不决定文档是否值得长期维护。

## 合并位置

- 功能目标、主要流程、页面状态、边界条件和长期验收事实通常合并到现有 `docs/features/<feature-slug>.md`。
- 多个功能共同遵守的稳定系统决策，只有通过架构文档准入时才进入 `docs/architecture/`。
- 多模块或多端共享的业务语义和数据规则，只有通过契约文档准入时才进入 `docs/contracts/`。
- 单页样式调整、临时需求和可随时从原型重新获得的普通细节，不建立长期项目文档。

同一主题只保留一份主文档。不要按页面、版本、人员或“原型需求/实现方案”复制平行文档。

## 区分事实

- MasterGo 是目标需求来源；当前代码是已实现事实。
- 两者未对齐时分别说明，不把计划状态写成已经完成。
- 可以记录原型链接、节点或页面标识和读取日期；不复制整份原型、data 包、Cookie 路径或 HTML 镜像。
- 图片只有在长期理解不可替代且文档治理允许时才精选保留，否则只引用原型来源。

新建、改名或废弃文档时同步更新 `docs/README.md`。项目文档完成后停止；源码实现重新按当前仓库规则路由。
