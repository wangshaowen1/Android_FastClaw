# MasterGo 读取与分析

## 选择读取方式

- 用户提供本地 Netscape Cookie Jar：优先走本地只读脚本，避免加载 MCP。
- 没有 Cookie Jar 且文件公开：先尝试匿名只读脚本。
- 需要读取当前选中图层、组件库、变量、DSL/D2C，或者修改 MasterGo 画布：这不是本地原型抽取范围，使用用户明确授权的官方 MCP。
- 一种认证方式失败后立即说明失败阶段，不携带 Cookie 自动切换到其他服务。

本地 Cookie 链路使用 MasterGo 页面接口，只作为只读适配器；接口字段或路径变化时允许失败，不能把旧路径当成长期公开契约。

## 运行脚本

使用 Python 3.9+。Windows 可用 `py -3`，macOS/Linux 可用 `python3`；下面用 `<python>` 代表当前平台的命令：

```text
<python> scripts/read_mastergo.py "<mastergo-url>" [--cookie-jar "<local-cookie-file>"] [--keyword "<业务词>"]
```

只检查 Cookie Jar 格式而不联网：

```text
<python> scripts/read_mastergo.py --check-cookie-jar "<local-cookie-file>"
```

脚本负责：

1. 校验链接和 Cookie 域名。
2. 解析 `documentId`，读取 metadata 和 `fileKey`。
3. 从当前页面或显式参数确认 `wv`，再下载 data 包。
4. 按用户提供的关键词限量提取上下文，并限量列出图片资源路径。
5. 在系统临时目录生成 `result.json` 和 `mastergo.data`；标准输出只给摘要，不输出 Cookie。

不要把整份 `mastergo.data`、完整 metadata 或无限制 `rg -a` 输出放进模型上下文。需要补充关键词时重新运行脚本，每次只搜索当前功能相关的少量词。

## Cookie 处理

- 文件首行必须是 Netscape Cookie File 标识。
- 只加载未过期的 `mastergo.com` Cookie；文件中其他域名的记录不发送。
- Cookie 文件放在业务仓库之外，不新增用于保存 Cookie 的仓库目录。
- 不把 Cookie 路径写进 `result.json`、项目文档或最终答复。
- 登录失效时请用户重新导出；不要尝试绕过登录、权限或验证码。

## 判断读取是否完整

按四层分别确认：

1. metadata：取得文件名、权限信息和 `fileKey`。
2. data：HTTP 成功、大小合理且不是错误文本。
3. 文本和页面：能定位目标页面、需求文字或相关图层上下文。
4. 图片：当视觉证据影响结论时，能定位并查看关键图片。

四层都满足才能说明“完整可读”。不需要视觉证据的纯文字需求可以明确说明图片层未核对；这属于“满足本次分析”，不是整份原型已完整读取。

## 提取哪些事实

只整理当前需求需要的内容：

- 页面或弹窗的用途、入口、返回和关闭方式。
- 加载、空态、成功、失败、未登录、无权限、禁用和选中等状态。
- 输入项、默认值、校验、关键文案和错误提示。
- 列表、刷新、分页、加载更多和空列表行为。
- 跳转目标、参数、返回结果和跨页面刷新要求。
- 接口时机、字段业务含义、后台配置、开关、埋点和跨端依赖。
- 图片、图标、封面、背景和插画等资源线索。

废弃页面只记录其废弃状态，不并入有效需求。冲突内容标成待确认，不自行裁决。

## 对照当前代码

准备输出结论或项目文档前，只搜索与当前功能直接相关的页面、路由、状态层、数据层、布局、资源和测试：

- MasterGo 表达目标设计。
- 当前代码表达已实现事实。
- 找到现有实现时写成改造；未找到时写成新增。
- 两者不一致时同时保留目标与现状，不把其中一方改写成另一方。

关键页面、关键状态或用户要求核对的图片无法读取时停止。只说明失败阶段、已确认范围和需要补充的资料，不生成代码或长期文档中的确定结论。
