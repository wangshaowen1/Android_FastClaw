# 接口与数据规则模板

用于多个模块或系统共同遵守的接口、事件、数据和状态规则。OpenAPI、Apikit、Proto 或等价 Schema 已能完整表达的结构，直接链接，不在 Markdown 重复维护。

```markdown
# <名称>

## 谁会使用、以什么为准

说明谁提供、谁使用、大家必须遵守什么行为，以及数据结构应查看 Schema、代码还是产品资料。

## 范围

直接说明本文约定哪些共同规则。数据库如何落表、页面如何展示、代码具体怎么写通常不在本文展开；只有容易混淆时才说明。

## 共同遵守的数据规则

记录 ID、空值、顺序、状态由谁维护、可见性、一致性和兼容规则。

## 接口、事件或数据

按业务功能组织真正需要写清的请求、响应、事件或字段含义。

## 状态怎么变化、出错后怎么办

描述幂等、并发、错误、重试和恢复中会影响使用方实现的行为。

## 版本变化怎么兼容

说明如何识别版本、哪些变化必须兼容、何时迁移以及旧数据怎么处理；没有特殊规则就删掉本节。

## 怎么联调和验收

列出各方都能检查的验收条件；项目使用契约测试时，链接对应测试。

## 还需要确认什么

只列会改变共同规则的问题；没有就删掉本节。
```

Schema 尚未建立时，Markdown 可以暂时定义必要字段。每个结构只保留字段表、完整示例或类型定义中的一种写法；Schema 建立后删掉重复结构，只保留 Schema 表达不了的业务规则、兼容方式和错误处理。
