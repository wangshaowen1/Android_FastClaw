# 项目导览模板

用于 docs/README.md。它只帮助新成员快速了解项目由哪些部分组成、主要流程如何运行，以及下一步该读什么。不重复根 README 的环境搭建，也不展开具体设计。

章节可按项目特点调整；标题应直接说明读者将了解什么，不要原样复制不符合当前项目的占位标题。

```markdown
# <项目名>开发者导览

## 项目是做什么的

用一个短段落说明产品用途、当前仓库负责什么，以及哪些内容需要去其他仓库或系统确认。

## 先了解这几件事

用 3–6 条说明新成员最需先知道的项目结构、入口和规则。

## 项目结构速览

| 项目部分 | 做什么 | 代码位置 | 继续阅读 |
| --- | --- | --- | --- |

只列理解和查找代码所需的主要部分。

## <直接说明内容的流程标题，例如“应用怎么启动和打开页面”>

只保留新成员理解项目必须知道的少量流程。

## 必须遵守的规则

只列理解或修改项目时必须知道、且容易误用的长期规则；详细原因链接到对应文档。

## 按任务查文档

| 要做什么 | 先看什么 |
| --- | --- |
| 第一次了解项目 | 给出第一次阅读项目文档的最短顺序 |
| 让 AI 修改项目 | 按任务类型指出需要加载的一份或少量文档 |

## AI 如何选择文档

- 普通代码任务不预读全部 docs；需要项目背景时，从本导览选择首轮要读的一份文档。
- 当前文档只有被本导览或当前任务选中后才读取；链接只是导航，不会自动触发继续读取。
- `history-only` 只在版本比较、回归、迁移、回滚或追溯决策时读取。

## 其他可查文档

| 文档 | 用途 | 状态 | 适用范围 |
| --- | --- | --- | --- |
```

不要列完整模块树、完整 API、每个页面、版本历史或与根 README 重复的内容。
